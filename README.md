# DeZheremoBot 🍽

Telegram-бот для групового чату, який допомагає компанії друзів вирішити, де поїсти
(зазвичай — снідати/бранч). Протягом тижня учасники пропонують варіанти закладів,
а після дедлайну бот випадково обирає один з них і оголошує переможця в чаті.

Назва — з українського сленгового "де ми жеремо?" 🙂

## Як це працює

- **Нагадування.** У задані дні й час бот надсилає в групу нагадування з кнопками
  "➕ Додати", "📋 Список" та "🙅 Не йду" — перші дві відкривають приватний чат з ботом.
  Нагадування, найближче до дедлайну (за замовчуванням — п'ятниця), додатково тегає тих,
  хто ще не відповів цього тижня (за історією минулих розіграшів), і повідомляє кількість
  учасників групи, яких бот ще ніколи не бачив (Telegram Bot API не дає списку всіх
  учасників чату, тож роздрукувати їх поіменно неможливо). Найперше нагадування тижня (якщо
  налаштовано кілька) має свій власний, м'якіший текст замість "хто ще не встиг".
- **Пропозиція варіанту.** Додавання/зміна варіанту відбувається лише в приватному чаті
  з ботом (щоб не спамити групу), у вигляді посилання на заклад — Google Maps, Instagram
  або expz.menu. У кожного учасника — один активний варіант на групу; повторне додавання
  його заміняє. Посилання в групі показуються як клікабельні (для Instagram — одразу
  видно юзернейм), а не як голий URL.
- **"Не йду цього тижня".** Замість того щоб просто мовчати, учасник може одним тапом
  (з приватного меню або прямо з кнопки "🙅 Не йду" в груповому повідомленні) відзначити,
  що пропускає цей тиждень — це виключає його з розіграшу і з тегування як "ще не
  відповів". Якщо перед цим у нього вже був поданий варіант, група отримує повідомлення,
  що варіант знято; скасувати "не йду" можна назад, і бот запропонує одним тапом повернути
  саме той варіант, який щойно було знято.
- **Дедлайн і розіграш.** У заданий час прийом заявок закривається, і бот одразу після
  цього випадковим чином обирає один із запропонованих варіантів та оголошує переможця в
  групі (з нагодою пожартувати, якщо той самий заклад виграв два тижні поспіль).
- **Оцінка закладу після розіграшу.** У свій день і час (за замовчуванням — неділя, 15:00)
  бот приватно запитує в кожного, хто подавав варіант того тижня, оцінку 1–5★ закладу, який
  група відвідала, — або "🙅 Мене не було", якщо не вдалось піти.
- **Свій розклад для кожної групи.** Адміністратор групи може налаштувати дні й час
  нагадувань, закриття прийому заявок, розіграшу та опитування-оцінки через команду
  `/schedule` у приватному чаті з ботом, а також надіслати нагадування в групу негайно
  кнопкою "🔔 Надіслати нагадування зараз", не чекаючи розкладу.
- **Керування циклом.** Команда `/admin` у приватному чаті відкриває панель з чотирма
  розділами:
  - **🔄 Цикл тижня** — призупинити/відновити тижневий цикл, форсувати розіграш просто
    зараз, повторно відкрити прийом заявок після закриття або скинути поточний тиждень без
    розіграшу;
  - **🚫 Учасники** — заблокувати/розблокувати конкретного учасника в цій групі (без
    впливу на інші групи, де є той самий бот);
  - **⭐ Опитування** — увімкнути/вимкнути автоматичне опитування-оцінку і за потреби
    надіслати його вручну — всім учасникам минулого тижня або обраним;
  - **🧪 Експериментальні функції** — поки що тут лежить статистика (🏆 топ закладів за
    кількістю перемог, 📈 хто найбільше пропонує варіантів і хто найбільше оцінює) — місце
    для нових фіч, які ще не доросли до постійного місця на головній панелі.

  Кожна зміна в `/admin` та `/schedule` записується у внутрішній журнал дій із зазначенням,
  який саме адмін це зробив (перегляду через UI поки немає).
- Бот сам реєструє групи, в які його додають/з яких видаляють — жодного налаштування
  chat id вручну не потрібно.
- **Довідка.** Команда `/help` у приватному чаті з ботом пояснює весь цикл вище простою
  мовою — для тих, хто бачить бота вперше. Усі "службові" команди (`/help`, `/schedule`,
  `/admin`) працюють лише в приватному чаті — набрані в групі, вони просто ігноруються, щоб
  не засмічувати групу; єдиний виняток — `/start`, який запускає меню групи.

## Технології

- Node.js + TypeScript (ESM)
- [Telegraf](https://telegraf.js.org/) — Telegram Bot API
- [node-cron](https://github.com/node-cron/node-cron) — щохвилинний тік для перевірки
  розкладу кожної групи
- `node:sqlite` (вбудований у Node.js) — зберігання поточного стану тижня та історії
  розіграшів, без зовнішньої БД
- [`@sentry/node`](https://docs.sentry.io/platforms/javascript/guides/node/) (опційно, лише
  якщо задано `SENTRY_DSN`) — трекінг помилок у продакшені, включно з Sentry Crons-моніторингом
  самого щохвилинного тіка

Якщо задано `DEZHEREMO_ALERT_CHAT_ID` (опційно, id Telegram-чату з ботом, куди слати
сповіщення), бот сам напише туди, якщо щохвилинний тік не спрацьовував понад 2 хвилини —
на додачу до Sentry Crons, а не замість нього: цей алерт ловить "тік завис", Sentry
Crons — ще й "процес взагалі впав".

## Запуск локально

Потрібен Node.js >= 22.5.0.

```bash
npm install
cp .env.example .env
```

У `.env` вкажіть `BOT_TOKEN` — токен **окремого, тестового** бота, отриманий у
[@BotFather](https://t.me/BotFather) (наприклад, `DeZheremoBot Dev`). Не використовуйте
той самий токен, що й у продакшн-боті: Telegram дозволяє лише одного отримувача
оновлень (`getUpdates`) на токен, тож локальний запуск проти продакшн-токена або впаде з
помилкою `409: Conflict`, або почне відповідати реальним учасникам реальної групи прямо
під час розробки. Додайте тестового бота до окремої тестової групи й тестуйте цикл там.

```bash
npm run dev     # запуск з hot reload (tsx watch)
npm test        # автотести (node:test)
npm run build   # перевірка типів + компіляція в dist/
npm start        # запуск скомпільованої версії (dist/bot.js)
```

## Розгортання (Fly.io)

Проєкт містить `Dockerfile` та `fly.toml`, налаштований на regio `fra` (Frankfurt) з
persistent volume під `data/` (там зберігаються `groupChats.json`, `groupSchedules.json`
та SQLite-файли стану й історії).

```bash
fly launch          # перший запуск — fly.toml вже є, можна пропустити перезапис
fly volumes create dezheremobot_data --region fra --size 1
fly secrets set BOT_TOKEN=<продакшн-токен>
fly secrets set DEZHEREMO_ALERT_CHAT_ID=<ваш telegram user id>   # опційно
fly deploy
```

Продакшн-токен має існувати лише як Fly secret і ніколи не потрапляти в локальний `.env`.

## Структура проєкту

```
src/
  bot.ts            точка входу — реєструє хендлери, запускає бота й планувальник
  scheduler.ts       щохвилинна перевірка розкладу кожної групи
  commands/          Telegraf-хендлери (тонкий шар, без бізнес-логіки)
  services/          бізнес-логіка: блокування, випадковий вибір, валідація розкладу
  storage/           доступ до даних: JSON-файли, SQLite, in-memory стан UI
  messaging/         announcements.ts, telegramBroadcast.ts — побудова й розсилка повідомлень у групи
  utils/             kyivTime.ts, htmlFormat.ts — дрібні хелпери без бізнес-логіки
data/                 groupChats.json, groupSchedules.json, state.db, history.db (гітигноряться)
```

## Тести

`npm test` запускає автотести (`node:test`) для `services/` і `storage/`, а також частини
`commands/`. Детальніше про підхід до тестування — у коментарях коду відповідних файлів.
